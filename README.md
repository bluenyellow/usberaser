# USB Eraser

A tiny Windows GUI tool that overwrites an entire drive in a **single pass**,
so what was on it can no longer be recovered with ordinary recovery software.

![what it does](https://img.shields.io/badge/platform-Windows-blue) ![python](https://img.shields.io/badge/python-3.8%2B-green)

The window, taskbar and exe all use a small **floppy-disk icon**
(`floppy.ico`, generated by `make_icon.py`).

---

## Wipe methods

Pick one in the *Method & confirmation* box before you erase:

| Method | What it writes | When to use it |
|---|---|---|
| **Zeros** | `0x00` over the entire device | Default. Fastest. The standard "quick wipe" for a USB stick you're handing to somebody else. |
| **Random data** | Cryptographically strong random bytes from `os.urandom` (`BCryptGenRandom` on Windows) | Slower, but leaves no fixed pattern behind. Hides any residual signal from the previous data and defeats naive "was this drive ever written to?" heuristics. |

Both methods destroy the partition table, every filesystem structure and every
file's contents. Only the byte pattern written differs.

## How to use it

1. Plug in the USB drive you want to erase.
2. Click **Refresh**.
3. Click the drive in the list. Check the panel underneath:

- disk number
- model name
- size
- volume letters
4. Choose the wipe method:

- **Zeros** — fast, default
- **Random data** — slower, stronger concealment
5. Type `ERASE` in the confirmation box.
6. Click **Erase drive** and confirm the warning dialog.
7. Wait for the progress bar to reach 100 %.
8. When it finishes, a green **✓ DONE** banner appears above the progress bar
and a small dialog pops up to confirm. Close the dialog and open
**Disk Management** (`Win + X` → *Disk Management*), find the now-empty
disk and create a new volume — otherwise Windows won't show it in Explorer.

## What "erased" actually means here

The tool writes a chosen byte pattern (all zeros, or a stream of random bytes)
from the first sector to the last sector of the raw device. That destroys:

- the partition table,
- every filesystem structure,
- every file's contents.

File-recovery tools that scan for deleted directory entries find nothing,
because there are no directory entries left — the whole surface is either
uniform zeros or pure noise.

### Honest limitations

- **Flash memory and wear levelling.** On SSDs and many USB sticks, the
controller may keep spare blocks (over-provisioning) that a host-level
overwrite never touches. A single pass — *regardless of whether it is zeros
or random* — is not guaranteed to reach those blocks. If you need a guarantee
on flash media, use the drive vendor's own utility (Samsung Magician,
SanDisk Dashboard…) and issue the ATA `SECURE ERASE` / NVMe `Format NVM`
command — that tells the controller itself to erase everything, including
spare blocks.
- **Bad sectors.** Anything the drive has already remapped away is unreachable
from the host. That is normally a good thing.
- **Physical destruction** is still the only 100 % method for truly sensitive
media.

## Troubleshooting

| Problem ↕▾ | Fix ↕▾ |
|---|---|
| −Erase button stays greyed out | Run as Administrator. Also make sure the disk isn't a system disk and that you typed `ERASE`. |
| −"Access is denied" while writing | Close Explorer windows, antivirus scanners and any other program touching the drive, then try again. |
| −The drive disappears after the wipe | Expected. Create a new volume in Disk Management. |
| −Random mode is much slower than zeros | Normal. Generating cryptographically strong random bytes is CPU-bound; the drive is no longer the bottleneck on fast USB 3 devices. |
| −No floppy icon in the title bar | Run `python make_icon.py` once to create `floppy.ico` next to `usb_eraser.py`. |
| −No drives listed | `Get-Disk` needs Windows 8 / Server 2012 or newer. Update PowerShell (`winget install Microsoft.PowerShell`). |
| −The exe is flagged by antivirus | Unavoidable for any tool that writes to `\\.\PhysicalDriveN`. Add an exclusion or run the Python script directly. |
